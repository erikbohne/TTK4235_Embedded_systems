\section{Doxygen-dokumentasjon}
Vi har generert Doxygen-dokumentasjon for prosjektet for å gi en detaljert oversikt over kodestrukturen og funksjonaliteten. Dokumentasjonen er organisert i følgende seksjoner:

\subsection{Filstruktur}
Prosjektet består av følgende hovedfiler:
\begin{itemize}
    \item \textbf{main.c}: Hovedfil med hovedløkken og overordnet tilstandshåndtering
    \item \textbf{state\_machine.h}: Definisjoner for tilstandsmaskin og datastrukturer
    \item \textbf{state\_functions.c/.h}: Implementasjon av tilstandsfunksjoner
    \item \textbf{input.c/.h}: Håndtering av knapper og lys
    \item \textbf{orders.c/.h}: Logikk for bestillingshåndtering
    \item \textbf{hardware.c/.h}: Grensesnitt mot heismaskinvaren
\end{itemize}

\subsection{Datastrukturer}
De viktigste datastrukturene i systemet er:

\begin{lstlisting}[style=cpp, caption=Hovedstrukturer i systemet]
/** Mulige tilstander for heisen */
typedef enum {
    INIT_STATE,           /**< Initieringstilstand */
    IDLE_STATE,           /**< Hviletilstand */
    MOVING_STATE,         /**< Bevegelsestilstand */
    DOOR_OPEN_STATE,      /**< Tilstand med åpen dør */
    EMERGENCY_STOP_STATE  /**< Nødstopptilstand */
} State;

/** Retning heisen beveger seg i */
typedef enum {
    DIR_DOWN = -1,  /**< Nedover */
    DIR_STOP = 0,   /**< Stopp */
    DIR_UP = 1      /**< Oppover */
} Direction;

/** Datastruktur som inneholder systemets tilstand */
typedef struct state_data {
    State state;                                     /**< Nåværende tilstand */
    int btnStates[HARDWARE_NUMBER_OF_FLOORS][HARDWARE_NUMBER_OF_BUTTONS]; /**< Status for alle knapper */
    Direction dir;                                   /**< Nåværende retning */
} state_data;
\end{lstlisting}

\section{Heisspesifikasjoner og kravspesifikasjon}
\subsection{Heismaskinvarespesifikasjoner}
Heismodellen har følgende egenskaper:
\begin{itemize}
    \item 4 etasjer (nummerert 0-3)
    \item 3 typer bestillingsknapper: opp, ned, og interne (cabinknapper)
    \item Etasjeindikatorer
    \item Stopknapp
    \item Obstruksjonssensor for døren
\end{itemize}

\subsection{Funksjonelle krav}
Heisstyringssystemet skal oppfylle følgende funksjonelle krav:

\begin{enumerate}
    \item \textbf{K1}: Heisen skal kunne bevege seg opp og ned mellom etasjer på en kontrollert måte.
    \item \textbf{K2}: Heisen skal stoppe ved etasjer presist og åpne døren.
    \item \textbf{K3}: Bestillingsknapper skal lyse når de trykkes og slukke når bestillingen er betjent.
    \item \textbf{K4}: Heisen skal betjene alle bestillinger, uavhengig av rekkefølgen de ble registrert.
    \item \textbf{K5}: Heisen skal prioritere bestillinger effektivt for å minimere total reisetid.
    \item \textbf{K6}: Heisen skal stoppe umiddelbart når stopknappen trykkes.
    \item \textbf{K7}: Heisen skal holde døren åpen hvis dørsensoren detekterer en obstruksjon.
    \item \textbf{K8}: Heisen skal kunne gjenopprette normal drift etter strømbrudd eller nødstopp.
\end{enumerate}

\subsection{Ikke-funksjonelle krav}
I tillegg til de funksjonelle kravene må systemet oppfylle følgende ikke-funksjonelle krav:

\begin{enumerate}
    \item \textbf{NFK1}: Systemet skal være pålitelig og robust mot uventede hendelser.
    \item \textbf{NFK2}: Systemet skal ha rask responstid på brukerinteraksjoner.
    \item \textbf{NFK3}: Koden skal være velstrukturert, modulær og lett å vedlikeholde.
    \item \textbf{NFK4}: Systemet skal gi tydelig tilbakemelding til brukeren gjennom lys og indikatorer.
    \item \textbf{NFK5}: Systemets oppførsel skal være intuitiv og forutsigbar for brukeren.
\end{enumerate}

Disse kravene har dannet grunnlaget for design, implementasjon og testing av heisstyringssystemet.
